# v1 feature contract

This document froze the shared contract for the v1 feature set (feature labels G3–G7, G10 and G12, plus
later additions listed below) so that the features could be implemented in parallel without touching
shared files. It covers domain types, state migrations, the OpenAPI document and Go wire types, guest
protocol messages, SDK models and capability entries. The freeze itself implemented none of the features:
only contracts, routing, thin fakes and tests. The status table below records what has shipped since.

## Rules for implementers

- **Not built means `not_implemented`.** Every new operation is in `api/openapi.yaml` with
  `x-davit-implemented: false` and a 501 response. It is routed with its real access rule
  (`internal/httpapi/parity.go`) and answers a typed `not_implemented` error. `details.feature` names the
  capability entry and `details.operation` the operationId. New *fields* on implemented operations
  (`createVM.environment`, `createPrompt.attachments`, …) are refused the same way in the owning service,
  never silently ignored.
- **Capabilities list every feature.** `HostCapabilities.features` (`domain.ParityFeatures`) names each
  feature, its gap, its operations/fields and its status. `HostCapabilities.harnesses` lists each
  harness's steer support, attachment types, reasoning efforts and fast mode. All of these start as
  not implemented, and steer starts as `unsupported`.
- **Shipping a feature:**
  1. Replace its `notImplemented` route with the real handler.
  2. Remove the field guard.
  3. Set `x-davit-implemented: true` and flip `expectedOperations` in `api/openapi_test.go`.
  4. Report the feature `available` (`lifecycle.Config.Features`).
  5. Add mutating operations to `cmd/davit/idempotency_test.go`.
  6. Wrap the operation in both SDKs and remove it from `NOT_YET_SUPPORTED`.

  `TestParityOperationsAnswerNotImplemented` checks that every unimplemented operation is routed, answers
  501 and is listed by its feature. It fails on a missing route or a missing capability entry.
- Shared files stay with the integrator: `api/`, `internal/domain/`, `internal/state/` migrations,
  `internal/guestproto/`, daemon wiring. Contract changes after this freeze go through one dedicated change,
  and the SDK models are regenerated once.

## Status

| Feature | State | What the guest side has to plug in |
| --- | --- | --- |
| `environments` | available: CRUD and revisions (`internal/lifecycle/environments.go`, `internal/httpapi/environments.go`, `davit env`) | nothing |
| `workspacePrepare` | available with a guest transport: lifecycle drives `pending → preparing → ready|failed` (`internal/lifecycle/workspace.go`) through `guestexec.Manager.PrepareWorkspace`, bound late in the daemon. Secret files resolve from the daemon's named secrets (`harness.secretsFile`). | nothing |
| `processHistory` | available: guestexec's collector retains output, keeping the newest 8 MiB per process (`internal/guestexec/output.go`). The oldest is dropped and the drop recorded. `internal/jobs` and `davit history` read it. `outputDropped` is set when output was trimmed, or when the guest evicted output before the host recorded it. `outputNotRetained: policy` is set instead when the VM's `noOutputRetention` policy withheld the output (the process ran under it, or a later turn-on purged it). The store records this per process as a seq −1 marker that outlives turning the policy off again. Withheld output never counts as `outputDropped`. `HistoryEntry.handle` comes from `processes.handle` (`ProcessRecord.Handle`). | nothing |
| `guestProcesses` | available with a guest transport: `listGuestProcesses` and `davit ps` sample through `guestexec.Manager.GuestProcesses`, which maps job handles and records the sample. A VM that is not running answers with its last sample (`stale`). | nothing |
| `runs` | available with a guest transport (`internal/runs`, `davit run`): orchestration over the lifecycle and process APIs, restart-safe (step keys derived from the run ID; the VM is named `run-<id>`); with an environment, the command waits for a ready workspace | nothing |
| `push` | available (`pushTree` with `mode=merge`; `internal/push.Git` selection; `davit push`). `mode=mirror` stays `not_implemented`. | Guest-side deletion, for mirror. |

Run behaviour to know:
- A run is terminal only after its cleanup (its VM is deleted unless `keep`).
- `outcome` and `decidedAt` give the result as soon as it is known; `state` follows once cleanup ends. After the command exits, the run keeps its VM for an output grace, so a client can still read the output. The grace defaults to 5 s, is set host-wide with `runs.outputGrace`, and per run with `outputGraceSeconds` (0: none). `cancelRun` on a decided run only ends the grace.
- A command killed by a signal ends `failed` with `signal` set and no `error`, like a non-zero exit.
- `listRuns` pages the caller's runs, oldest first.
- A run's `env` values are kept in the host database only until its command starts (or the run ends without one); then only the names remain. They must survive until then, because a restarted daemon may have to re-issue the keyed exec, which needs the identical request.

## Tests that pin the contract

- `api/openapi_test.go`: every schema matches its Go type by reflection, including the new enums
  (`FeatureStatus`, `SteerSupport`, `WorkspaceState`, `CredentialKind`, `GrantState`, `RevokeReason`,
  `RunState`), and all 30 operations are listed as unimplemented with a 501.
- `internal/httpapi/parity_test.go`: every unimplemented operation answers 501 naming a feature that lists
  it. The environment fields are refused on createVM/forkVM/resumeVM.
- `internal/harness` `TestPromptContractFieldsRefused`; `internal/domain/parity_test.go` (feature
  registry, manifest validation, grant revoke table); `internal/state/parity_test.go` (stores);
  `internal/credproxy` `TestGrantContract`; `internal/push` `TestValidateSelection`;
  `internal/guestproto/messages_test.go` (round trip and validation of every new message).
- SDKs: models regenerated from this document, and the 30 operations listed in `NOT_YET_SUPPORTED`
  (both contract suites fail on an unlisted operation).
